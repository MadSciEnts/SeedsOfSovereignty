# SEED OF SOVEREIGNTY: AGENT HIERARCHY & ROLES (v0.5.3)

This project utilizes a tiered agent system to maintain architectural integrity across 48 tiers of evolution.

## 1. THE COMMAND CHAIN

### TIER 0: THE DEVELOPER (User)
- **Role:** Ultimate Authority.
- **Responsibility:** Onboarding agents and relaying session-aware handoff strings.

### TIER 1: AGENT IN CHARGE / LEAD ARCHITECT (Me)
- **Role:** Strategic Orchestrator.
- **Responsibility:** High-level planning and management of the `OB_*.md` mission files.

### TIER 2: FORENSIC COORDINATOR (Middle Man)
- **Role:** Tactical Supervisor.
- **Responsibility:** Manages `OB_SURGICAL_IMPLEMENTER.md`, verifies work with Rule #12 audits, and maintains a single Implementer session.

### TIER 3: SURGICAL IMPLEMENTATION AGENT (Implementer)
- **Role:** Pure Execution.
- **Responsibility:** Reads its `OB_*.md` file and modifies code. Prohibited from delegating tasks.

## 2. THE HANDOFF PROTOCOL (v0.5.2 - Session-State)
Every handoff prompt MUST begin with one of two session state declarations:

- **`[SESSION: NEW]`**: Indicates a fresh onboarding. The receiving agent must perform a full Rule #12 audit to establish ground truth from the disk.
- **`[SESSION: CONTINUING]`**: Indicates a handoff to a currently active agent. The agent may leverage its existing conversational context.

## 3. THE SINGLE BLADE RULE (v0.5.3)
- To prevent context loss and fragmentation, a T2 Coordinator must maintain a single, persistent T3 Implementer session for the entire duration of a mission phase.
- T3 Implementers are explicitly forbidden from creating or modifying onboarding files.
