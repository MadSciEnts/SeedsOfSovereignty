# Agent Protocols & Design Paradigms

## 1. The "No God Script" Policy
*   **Single Responsibility:** No file shall exceed 300 lines. If it does, it must be decomposed into smaller utility classes or specialized systems.
*   **Package Isolation:** Agents must stay within their assigned package. Logic (Math/Physics) must NEVER import UI (Compose) classes.
*   **Stateless Logic:** Systems must be functions or objects that take a `State` and return/mutate it. Avoid internal state within logic classes to prevent synchronization bugs.

## 2. Communication & State Management
*   **The Single Source of Truth:** All game data resides in `com.seedsofsovereignty.model`.
*   **Immutable Data:** Use Kotlin `data class` with `val` properties where possible. Use `.copy()` for state transitions.
*   **StateFlow Driven:** The UI (Compose) observes a `StateFlow` from the `GameViewModel`. It does not "pull" data; it reacts to changes.

## 3. Design Paradigms
*   **Functional Pipeline:** Input -> Logic -> State Update -> Render.
*   **Contract-First Development:** Interfaces must be defined in the `core` or `model` packages before implementation begins.
*   **Composition over Inheritance:** Ships are composed of `Modules` and `ChassisParts`, not inherited from a `BaseShip` class.

## 4. Asset & Performance Rules
*   **Procedural First:** No PNGs or JPGs. All textures must be generated by `factory` classes and cached as `ImageBitmap`.
*   **Normal-Mapped Lighting:** All ships must have a Diffuse, Normal, and Emissive map generated for real-time 2D shading.
*   **Memory Safety:** Use an `AssetRegistry` to prevent re-generating textures every frame. Use `DrawScope.drawWithCache` in Compose.

## 5. Agent Handoff Protocol
*   Before starting a task, an agent must read the `SoS_Project/` documentation relevant to their module.
*   **SACRED DOCUMENTATION:** Files within the `SoS_Project/` directory are **SACRED**. Agents (excluding the T1 Project Lead) are strictly prohibited from editing these files. They are for reference only.

## 6. Self-Monitoring & Response Limits
*   **Context Awareness:** Agents MUST indicate their current context and logic loads at the start and end of every major response.
*   **Format:** `-[ current / max :: Category ]-`
*   **Categories:** 
    *   `Context`: Project-wide awareness (Files/Modules/Tiers).
    *   `Logic`: Complexity of the current active task.
    *   `Tokens`: Estimate of response length vs limit (to prevent cutoff).
*   **Prevention:** If an agent feels a response will hit a "wall," they must pause and ask for a continuation.
